# 来源文档提取

## 本地文件

| 类型 | 处理方式 |
|---|---|
| `.md`、`.txt`、`.html` | 读取正文，保留标题、表格、代码块和示例 JSON |
| `.docx` | 使用可用的 Word 文档读取能力提取段落、表格和批注 |
| `.pdf` | 使用可用的 PDF 读取能力；扫描件先 OCR，并标记低置信度内容 |
| OpenAPI、Swagger JSON/YAML | 保留原文件，直接校验，不重新解释 |

不要只提取连续文本。接口路径、方法、参数表、请求示例和响应示例通常分布在不同结构中，需要按章节关联。

## 在线文档

1. 先判断 URL 是否直接指向 OpenAPI JSON/YAML；是则下载到新文件并保留来源 URL。
2. 对文档站点优先尝试在页面 URL 后加 `.md`，并检查站点提供的 `llms.txt`。Markdown 中若声明完整 OpenAPI JSON/YAML 地址，优先读取该规范作为事实来源。
3. 只有 `.md`、`llms.txt` 和公开规范文件不存在或内容不完整时，才使用浏览器读取页面。
4. 动态渲染、分页或折叠内容使用浏览器逐页展开并读取；API 文档必须展开嵌套字段、子属性、请求示例和全部响应状态标签，记录已覆盖的目录范围。
5. 需要登录时使用有头浏览器，让用户自行完成登录；不要索取或保存账号密码、Cookie。
6. 页面无权访问、验证码无法完成、禁止导出或正文加载不完整时停止，请用户授权或提供 PDF、DOCX、Markdown 导出文件。
7. 对 `https://geekai.co/` 页面按宿主项目约定优先通过 `https://r.jina.ai/` 前缀读取。

## 事实清单

对每个接口先整理：

- 业务域、接口名称、HTTP 方法、路径和用途
- 路径、查询、Header、Cookie 参数及其类型、必填性、约束和示例
- 请求内容类型、请求体字段和示例
- 响应状态码、响应内容类型、响应字段和示例
- 鉴权方式、公共参数、错误码、幂等或分页规则
- 来源章节或 URL，以及 `explicit`、`derived`、`inferred` 置信度

只有 `explicit` 和可机械推导的 `derived` 内容可以直接作为确定约束。`inferred` 内容必须显式标记并在导入前汇报。
