# lk888 Grok 图生视频上游

Base URL：`https://api.lk888.ai`（可用 `LK888_BASE_URL` 覆盖）

鉴权（推荐）：`Authorization: Bearer $LK888_API_KEY`

> 不要与 xAI 官方 Grok 视频接口混用同一 schema。  
> 业务展示名：`grok-video-3.5`  
> 实际上游 model：`grok-imagine-video-1.5-preview`

## 定位

| 项目 | 值 |
|------|-----|
| 类型 | **仅图生视频** |
| 输入 | 1 张首帧 + prompt |
| 输出 | 自带音频的视频 |
| 时长 | 1–15 秒 |
| 分辨率 | `480p` / `720p` |
| 比例 | `16:9` `9:16` `1:1` `3:2` `2:3` |

不支持：文生视频、多图参考、视频参考、音频参考。

## 接口

创建：

```
POST /v1/media/generate
Content-Type: application/json
```

```json
{
  "model": "grok-imagine-video-1.5-preview",
  "prompt": "...",
  "params": {
    "images": ["https://... or data:image/png;base64,..."],
    "aspect_ratio": "16:9",
    "resolution": "720p",
    "duration": "6"
  },
  "notify_url": "https://example.com/webhook"
}
```

注意：`notify_url` 是**顶层**字段，不要塞进 `params`。

查询：

```
GET /v1/media/status?task_id={task_id}
```

## 状态判断

只用机器字段：

| 字段 | 用途 |
|------|------|
| `is_final` | 是否终态 |
| `state` | `pending` / `running` / `success` / `failed` |
| `progress` | 展示用字符串 |
| `result_url` | 成功结果 |
| `error` | 失败原因 |

`status` / `status_group` 为中文展示，**不要**参与程序分支。

逻辑：

- `is_final === false` → 继续等
- `is_final && state === "success"` → 下载 `result_url`
- `is_final && state === "failed"` → 读 `error`

## 限制

| 项目 | 限制 |
|------|------|
| images 数量 | 必须 1 |
| 单文件 base64 解码后 | ≤ 10MB |
| 全部 base64 | ≤ 30MB |
| 请求体 | ≤ 50MB |
| 常见耗时 | 5–60 分钟 |
| 建议超时 | ≥ 70 分钟 |

## Webhook

`notify_url` 在成功/失败时 POST，body 与 status 查询一致；投递最多 4 次，不保证必达。  
**即使配置了 webhook，本 skill 仍以轮询兜底。**

## 与 xAI 官方差异（摘要）

| 项目 | LK888 | xAI 官方 |
|------|-------|----------|
| 创建 | `/v1/media/generate` | `/v1/videos/generations` |
| 查询 | `/v1/media/status?task_id=` | `/v1/videos/{request_id}` |
| 结构 | `model` + `prompt` + `params` | 顶层字段 |
| 图片 | `params.images` | `image` / `reference_images` |

## 接入建议

1. 单独渠道配置，映射展示名 `grok-video-3.5` → 真实 model。
2. 前端强制 1 张首帧。
3. 终态只看 `is_final` + `state`。
4. webhook 加速 + 轮询兜底。
5. base64 上传做大小校验。
